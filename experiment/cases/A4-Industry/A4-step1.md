
根据提供的来源《Agentic AI Use Cases and Requirements》（IETF Internet-Draft, 2026），该来源对“Agent”（AI Agent）的要求区分如下：

### 1. 明确要求的能力/属性

这些属性在来源的“术语”（Terminology）定义或“引言”（Introduction）中被明确规定为 AI Agent 的核心组成要素。

* **自主性（Autonomy）**：被定义为“一种自主的软件实体” 或“自主的、自适应的智能软件系统”。
* **感知与行动（Perception & Action）**：必须能够“感知其环境”并“执行动作”。
* **维持内部状态（Maintaining Internal State）**：在定义中明确要求 Agent 需“维持内部状态”。
* **目标导向性（Goal-oriented）**：Agent 必须为了“实现特定目标” 或“代表用户或其他 AI Agent 完成特定目标”而运行。
* **推理能力（Reasoning）**：Agent 需根据其“目标和上下文进行推理”，并基于推理结果采取行动。
* **动态决策（Dynamic Decision Making）**：与遵循固定执行路径的传统软件不同，Agent 必须能够在运行时“动态决定采取哪些操作、调用哪些工具以及与哪些 Agent 协作”。
* **自适应性（Adaptive）**：被明确定义为一种“自适应的”系统。
* **可识别性与可认证性（Identity & Authentication）**：来源要求 Agent 必须有关联的“身份信息”，用于在系统中进行“身份验证和问责”。在通信协议要求中，明确规定所有通信方之间必须进行“相互身份验证（Mutual authentication）”。

### 2. 来源反复强调但未明确规定为必要条件的属性

这些属性在多个用例中出现，但在核心定义中被描述为“潜在的”或针对特定场景的要求。

* **与其他 Agent 通信或协作的能力**：在定义中，这被描述为“**可能（potentially）**包括与其他 Agent 通信”。虽然整个文档都在讨论 Agent 间的通信协议，但在定义层面，这并非所有 Agent 存在的绝对必要条件。
* **调用外部工具的能力**：定义中称其“**可能**包括调用外部工具”。
* **多模态支持（Multimodality）**：来源要求 Agent 协议必须支持多种输入和输出模态（如文本、音频、图像、视频）。虽然在“单一 Agent 任务”用例中要求 Agent 与客户端协商模态，但未将其列为 Agent 定义的固有属性。
* **不透明性（Opaqueness）**：在对等协作多 Agent 场景中提到“每个 Agent 对其他 Agent 保持不透明，仅通过协议接口进行协作”，但这更多是协作模式的特征，而非对所有 Agent 的强制属性要求。

### 3. 只是实现方式，而非 Agent 概念本身的属性

这些内容属于实现 Agent 功能的技术手段或外部约束，不属于 Agent 这一概念的定义属性。

* **使用 AI 模型（Uses AI models）**：来源提到 AI Agent 是“使用 AI 模型来完成特定目标的软件系统”。这说明 AI 模型是实现 Agent 智能的工具或手段。
* **无状态的推理调用（Stateless Inference）**：来源指出“AI 模型本质上是无状态的”，每次推理仅处理显式提供的上下文。
* **应用层维护上下文（Context Maintenance）**：由于模型本身无状态，来源规定由“应用层负责维护上下文”，通过携带对话历史、中间结果和任务状态来实现。
* **遵循特定网络协议**：如 CMN-3 要求所有流量必须加密和完整性保护，CMN-7 要求支持加密算法敏捷性。这些是 Agent 接入该系统时必须遵守的协议规范，而非 Agent 概念本身的定义。
* **任务委派机制（Delegation Mechanism）**：通过凭证（credential）向工具提供商证明授权，而不暴露原始凭证。这是一种安全实现授权的方式。

### 总结

若来源未提及某项属性（如：**长期记忆、自我意识、道德准则**等），则**未明确**。该来源的核心关注点在于 Agent 作为一个能推理、有身份、可动态决策并能通过协议进行安全通信的自主软件实体。
